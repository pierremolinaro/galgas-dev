\subsection{\texttt{self}}\index{self}

Dans une expression, \ggsq+self+ représente une copie de l'objet courant. On ne peut donc utiliser \ggsq+self+ que dans une expression à l'intérieur d'une \emph{méthode}, d'un \emph{getter}, d'un \emph{setter}, ou d'une extension (\refChapterPage{chapitreExtensions}). Sont donc exclues les procédures et les fonctions.

\ggsq+self+ effectue un accès en lecture seule de l'objet courant.

Voici un exemple extrait de la section décrivant les \emph{extensions de getter} (\refSectionPage{categoryGetter}) :
\begin{galgas4}
getter @uint64 square -> @uint64 outResult {
  outResult = self * self
}
\end{galgas4}








\subsectionLabel{Expression de conversion polymorphique inverse}{expConversionPolymorphiqueInverse}

\fbox{\begin{minipage}{1.0\textwidth}
Cette construction est obsolète, et est remplacée avantageusement par l'\emph{affectation conditionnelle} (\refSubsectionPage{affectationConditionnelle}).
\end{minipage}}

La syntaxe de l'\emph{expression de conversion polymorphique inverse} est :

\begin{galgas4box}
expression as @T
\end{galgas4box}

Elle permet de renvoyer la valeur de \ggsq+expression+ sous la forme d'un objet de type statique \ggsq+@T+. À l'exécution, la conversion échoue si le type dynamique de l'\ggsq+expression+ n'est pas \ggsq+@T+ ou une de ses classes héritières~; une erreur sémantique est alors déclenchée, et l'expression renvoie un objet \emph{non construit}.

Pour tester le type dynamique de l'expression avant d'effectuer la conversion, utiliser la construction décrite à la \refSubsectionPage{testTypeDynamiqueExpression}. On peut aussi utiliser l'instruction \ggsq+cast+ (\refSectionPage{instructionCast}).







\subsectionLabel{Test du type dynamique d'une expression}{testTypeDynamiqueExpression}

L'opérande \ggsq+expression is conversion @T+ teste le type dynamique de \ggsq+expression+ vis à vis du type \ggsq+@T+ :
\begin{itemize}
\item si \ggsq+conversion+ est \ggsq+==+, la valeur renvoyée est \ggsq+true+ si le type dynamique de l'\ggsq+expression+ est exactement \ggsq+@T+, et \ggsq+false+ dans le cas contraire~;
\item si \ggsq+conversion+ est  \ggsq+>=+, la valeur renvoyée est \ggsq+true+ si le type dynamique de l'\ggsq+expression+ est \ggsq+@T+ ou une de ses classes héritières, et \ggsq+false+ dans le cas contraire~;
\item si \ggsq+conversion+ est  \ggsq+>+, la valeur renvoyée est \ggsq+true+ si le type dynamique de l'\ggsq+expression+ n'est pas \ggsq+@T+ mais une de ses classes héritières, et \ggsq+false+ dans le cas contraire.
\end{itemize}



Alliée à la construction précédente, elle permet de lancer une conversion uniquement si elle est possible :

\begin{galgas4}
if expression is == @B then
  let @B cst = expression as @B
  ...
elsif expression is >= @C then
  let @C cst = expression as @C
  ...
else
  message "conversion impossible"
end
\end{galgas4}

\subsection{Constante entière}

Une constante entière est une séquence de chiffres décimaux, éventuellement séparés par le caractère de soulignement \texttt{\_}, et terminé par un suffixe. Ce suffixe détermine le type de la constante :
\begin{itemize}
  \item pas de suffixe : \ggsq+@uint+~;
  \item suffixe \texttt{S} : \ggsq+@sint+~;
  \item suffixe \texttt{L} : \ggsq+@uint64+~;
  \item suffixe \texttt{LS} : \ggsq+@sint64+~;
  \item suffixe \texttt{G} : \ggsq+@bigint+.
\end{itemize}

\subsection{Constructeur}

L'appel d'un constructeur instancie un nouvel objet. Sa syntaxe est :

\begin{galgas4box}
@T.constructeur {!exp0 !exp1 ...}
\end{galgas4box}

Par exemple :
\begin{galgas4}
@lstring ls = @lstring.new {!"" !@location.here{}}
@stringlist str = @lstringlist.emptyList {}
\end{galgas4}

Deux simplifications syntaxiques sont proposées :
\begin{itemize}
  \item si la liste des arguments est vide, les accolades peuvent être omises~;
  \item si le type peut être inféré, il peut être omis.
\end{itemize}


\subsubsection{Suppression des accolades}

Si la liste des arguments est vide, les accolades peuvent être omises.

\begin{galgas4}
@lstring ls = @lstring.new {!"" !@location.here}
@stringlist str = @lstringlist.emptyList
\end{galgas4}



\subsubsection{Inférence du type}

Si le type peut être inféré, il peut être omis (remarquer que ceci est valable aussi pour \ggsq+@location.here+ qui peut être simplifié en \ggsq+.here+.

\begin{galgas4}
@lstring ls = .new {!"" !.here}
@stringlist str = .emptyList
\end{galgas4}

















\subsectionLabel{Valeur d'une option}{appelOption}

Les options de la ligne de commande sont définies dans un composant \ggsq+option+ (\refChapterPage{composantOption}). L'opérande \emph{appel d'option} permet d'obtenir des informations sur une option.

Sa syntaxe est \ggsq+[option nom_composant_option.nom_option nom_info]+, où :
\begin{itemize}
  \item \ggsq+nom_composant_option+ est le nom du composant \ggsq+option+ qui déclare l'option~;
  \item \ggsq+nom_option+ est le nom donné à l'option lors de sa déclaration~;
  \item \ggsq+nom_info+ est le nom de l'information dont la valeur sera retournée par l'opérande.
\end{itemize}


Les informations qui peuvent être ainsi obtenues sont décrites dans le \refTableau{infosDeAppelOption}.
\begin{table}[t]
  \centering
  \begin{tabular}{llll}
  \textbf{nom\_info} & \textbf{Commentaire}  & \textbf{Type de la valeur retournée}\\
  \ggsq+value+ & Valeur de l'option & \ggsq+@T+ (le type de l'option)\\
  \ggsq+char+ & Caractère d'appel de l'option & \ggsq+@char+\\
  \ggsq+string+ & Chaîne d'appel de l'option & \ggsq+@string+\\
  \ggsq+comment+ & Description de l'option & \ggsq+@string+\\
  \end{tabular}
  \caption{Informations relatives à une option de la ligne de commande}
  \labelTableau{infosDeAppelOption}
\end{table}

Par exemple, si un composant \ggsq+option+ est déclaré comme suit :
\begin{galgas4}
option mesOptions {
  @bool extractOption : 'S', "asm" -> "Extract assembly code"
}
\end{galgas4}

Alors :
\begin{itemize}
  \item \ggsq+[option mesOptions.extractOption value]+ renvoie un \ggsq+@bool+ qui vaut \ggsq+true+ si l'option a été activée, \ggsq+false+ dans le cas contraire~;
  \item \ggsq+[option mesOptions.extractOption char]+ renvoie un \ggsq+@char+ qui vaut \ggsq+'S'+~;
  \item \ggsq+[option mesOptions.extractOption string]+ renvoie un \ggsq+@string+ qui vaut \ggsq+"asm"+~;
  \item \ggsq+[option mesOptions.extractOption comment]+ renvoie un \ggsq+@string+ qui vaut \ggsq+"Extract assembly code"+.
\end{itemize}

Noter qu'à partir de la version 3.1.4, les options \emph{quiet} et \emph{verbose} (\refSubsectionPage{optionsQuietVerbose}) ne peuvent pas être appelées par cette construction : il faut utiliser le \refConstructorPage{application}{verboseOutput}.

\subsectionLabel{Arithmétique}{operateursArithmétique}

GALGAS propose des opérateurs arithmétiques qui détectent les dépassements de capacité : \ggsq*+*, \ggsq+-+, \ggsq+*+. Une erreur est déclenchée à chaque débordement.

L'opérateur de division \ggsq+/+ déclenche une erreur lors d'une division par zéro. Pour les types signés, une erreur est aussi déclenchée par la division de \ggsq+@sint.min+ par \ggsq+-1S+, et la division de \ggsq+@sint64.min+ par \ggsq+-1LS+.

Ces opérateurs ne détectent pas un dépassement de capacité : \ggsq*&+*, \ggsq+&-+, \ggsq+&*+, et fonctionnent donc comme les opérateurs arithmétiques du C.

L'opérateur de division \ggsq+&/+ ne déclenche aucune erreur lors d'une division par zéro, la valeur renvoyée est zéro. La division de \ggsq+@sint.min+ par \ggsq+-1S+ retourne \ggsq+@sint.min+, et celle de \ggsq+@sint64.min+ par \ggsq+-1LS+ retourne \ggsq+@sint64.min+.

L'opérateur \ggsq+mod+ déclenche une erreur en cas de division par zéro.

La négation arithmétique (opérateur \ggsq+-+ unaire) est uniquement définie sur les types entiers signés, et détecte les débordements provoqués par \ggsq+- @sint.min+ et \ggsq+- @sint64.min+.

Il existe un second opérateur de négation arithmétique (\ggsq+&-+), lui aussi uniquement défini sur les types entiers signés, qui ne détecte aucun débordement: \ggsq+&- @sint.min+ renvoie \ggsq+@sint.min+ et \ggsq+&- @sint64.min+ renvoie  \ggsq+@sint64.min+.


On peut tester l'absence de débordement grâce aux \emph{getters} \ggsq+canAdd+, \ggsq+canSubstract+, \ggsq+canMultiply+ et \ggsq+canDivide+, définis pour les quatre types \ggsq+@uint+, \ggsq+@uint64+, \ggsq+@sint+ et \ggsq+@sint64+. Si ces \emph{getters} renvoient \ggsq+true+, alors les opérations correspondantes s'effectueront sans débordement. Par exemple :
\begin{galgas4}
@uint a = ...
@uint b = ...
if [a canAdd !b] then
  @uint r = a + b # Pas de débordement
else
  # L'addition provoquerait un débordement
end
\end{galgas4}
