\section{Rôle du point-virgule «\texttt{;}»}

Le point-virgule n'est pas un terminateur d'instruction. Il représente une instruction vide. Aussi, il peut être utilisé en nombre quelconque entre deux instructions consécutives. Ainsi, on peut écrire~:

\begin{galgas4}
instruction1  instruction2
\end{galgas4}

Ou encore~:
\begin{galgas4}
instruction1 ; instruction2
\end{galgas4}
\begin{galgas4}
instruction1 ;;;; instruction2
\end{galgas4}







\section{Instruction de déclaration de variable}


Une déclaration de variable peut citer une \ggsq+expression+ qui lui fournit sa valeur initiale. Dans le cas contraire, la variable est \emph{non initialisée} jusqu'à ce qu'une valeur lui soit affectée.

Les deux formes de déclaration sont donc~:
\begin{itemize}
\item déclaration d'une variable \emph{non initialisée}~: « \ggsq+var @type variable+ »~;
\item déclaration d'une variable \emph{initialisée}~: « \ggsq+var @type variable = expression+ ».
\end{itemize}


\subsection{Déclaration « \texttt{var @type variable} »}

La forme générale de déclaration d'une variable \emph{non initialisée} est~:
\begin{galgas4box}
var @type variable
\end{galgas4box}


\subsectionLabel{Déclaration « \texttt{var @type variable = expression} »}{declarationVariableAvecExpression}



La forme générale de déclaration d'une variable \emph{initialisée} est~:
\begin{galgas4box}
var @type variable = expression
\end{galgas4box}

On peut omettre le type, à la condition que l'expression puisse fournir l'information de type. Par exemple, dans l'écriture suivante~:
\begin{galgas4}
var s = "Hello" # Type implicite @string
\end{galgas4}


Prenons un autre exemple, celui de l'initialisation d'une liste~:
\begin{galgas4}
var @stringlist sl = @stringlist {}
\end{galgas4}

Le type est annoté de façon redondante, puisqu'il apparaît à la fois dans le membre de gauche et dans l'expression~; l'une des deux annotations peut être omise~:
\begin{galgas4}
var sl = @stringlist {}
\end{galgas4}

Ou~:
\begin{galgas4}
var @stringlist sl = {}
\end{galgas4}

Par contre, omettre les deux annotations ne permet pas de déduire le type de la variable~; c'est donc une erreur détectée par le compilateur~:
\begin{galgas4}
var sl = {} # Erreur : le type est indéterminé
\end{galgas4}

Un dernier exemple, avec un constructeur~:
\begin{galgas4}
var @location sl = @location.here
\end{galgas4}

On peut écrire~:
\begin{galgas4}
var sl = @location.here
\end{galgas4}

Ou~:
\begin{galgas4}
var @location sl = .here
\end{galgas4}

Mais en aucun cas~:
\begin{galgas4}
var sl = .here # Erreur : le type est indéterminé
\end{galgas4}





\section{Instruction de déclaration de constante}

Une déclaration de constante peut citer une \ggsq+expression+ qui lui fournit sa valeur initiale. Dans le cas contraire, la variable est \emph{non initialisée} jusqu'à ce qu'une valeur lui soit affectée.

Les deux formes de déclaration sont donc~:
\begin{itemize}
\item déclaration d'une constante \emph{initialisée}~: « \ggsq+let @type constante = expression+ ».
\item déclaration d'une constante \emph{non initialisée}~: « \ggsq+let @type constante+ »~;
\end{itemize}

\subsection{Déclaration d'une constante initialisée}


Le mot clé \ggsq+let+ caractérise une déclaration de constante. L'annotation de type peut être omis si le type peut être déduit de l'expression, comme pour l'instruction de déclaration de variable (\refSubsectionPage{declarationVariableAvecExpression}). On peut donc reprendre les exemples de la section précédente~:
\begin{galgas4}
let @string s = "Hello"
\end{galgas4}

L'expression est une chaîne de caractères, dont le type est \ggsq+@string+. On peut donc omettre l'annotation de type dans l'instruction~:
\begin{galgas4}
let s = "Hello"
\end{galgas4}


Prenons un autre exemple, celui de l'initialisation d'une liste~:
\begin{galgas4}
let @stringlist sl = @stringlist {}
\end{galgas4}

Le type est annoté de façon redondante, puisqu'il apparaît à la fois dans le membre de gauche et dans l'expression~; l'une des deux annotations peut être omise~:
\begin{galgas4}
let sl = @stringlist {}
\end{galgas4}

Ou~:
\begin{galgas4}
let @stringlist sl = {}
\end{galgas4}

Par contre, omettre les deux annotations ne permet pas de déduire le type de la constante, c'est donc une erreur détectée par le compilateur~:
\begin{galgas4}
let sl = {} # Erreur : le type est indéterminé
\end{galgas4}

Un dernier exemple, avec un constructeur~:
\begin{galgas4}
let @location sl = @location.here
\end{galgas4}

On peut écrire~:
\begin{galgas4}
let sl = @location.here
\end{galgas4}

Ou~:
\begin{galgas4}
let @location sl = .here
\end{galgas4}

Mais en aucun cas~:
\begin{galgas4}
let sl = .here # Erreur : le type est indéterminé
\end{galgas4}


\subsection{Déclaration d'une constante non initialisée}

Il est possible de déclarer une constante sans fournir de valeur initiale. Une seule affectation est alors permise.

\begin{galgas4}
let @string s
...
s = "Hello"
...
s = "World" # Erreur sémantique, une constante ne peut pas être modifiée
\end{galgas4}

L'intérêt est de pouvoir initialiser la constante dans chaque branche d'une instruction sélective~:
\begin{galgas4}
let @string s
if ... then
  s = "Hello 1"
else
  s = "Hello 2"
end
\end{galgas4}












\sectionLabel{L'instruction d'affectation}{assignmentInstruction}

L'instruction d'affectation peut prendre plusieurs formes. La plus courante est~:

\begin{galgas4box}
variable = expression
\end{galgas4box}

Si \ggsq+variable+ est une instance de structure (\refChapterPage{typeStructure}), on peut directement en modifier un champ en utilisant l'opérateur \ggsq+.+~:

\begin{galgas4box}
variable.champ = expression
\end{galgas4box}

Si \ggsq+champ+ est lui-même une structure, on peut accéder à l'un de ses champs (et ainsi de suite)~:

\begin{galgas4box}
variable.champ.champ1 = expression
\end{galgas4box}














\subsectionLabel{Instruction d'ajout et les listes}{instructionConcatList}

Sous la forme \ggsq*cible += expression*, l'instruction effectue une concaténation de listes~: \ggsq+cible+ et \ggsq+expression+ doivent avoir le même type \ggsq+list @T+, et l'\ggsq+expression+ est ajoutée à la fin de la \ggsq+cible+.

\begin{galgas4}
var liste1 = @stringlist {!"a", !"b"}
var liste2 = @stringlist {!"c", !"d"}
liste1 += liste2 # liste1 vaut "a" "b" "c" "d"
\end{galgas4}



Sous la forme \ggsq*cible += !expression1 ... !expressionN*, l'instruction ajoute un élément à la fin de \ggsq+cible+. L'élément est défini par la liste des valeurs de ses champs.

Avec la liste~:
\begin{galgas4}
list @maListe {
  @u32 mProperty1
  @string mProperty2
}
\end{galgas4}

On a~:

\begin{galgas4}
var liste = @maListe {}
liste += !2 !"a" # liste vaut contient un élément 2, "a"
\end{galgas4}






\subsectionLabel{Instruction d'ajout et les listes triées}{instructionConcatSortedList}

Sous la forme \ggsq*cible += expression*, l'instruction effectue une concaténation de listes~: \ggsq+cible+ et \ggsq+expression+ doivent avoir le même type \ggsq+sortedlist @T+, et chaque élément de \ggsq+expression+ est ajouté à la \ggsq+cible+ en respectant l'ordre de tri.

Avec la liste triée~:
\begin{galgas4}
sortedlist @maListeTriee {
  @u32 mProperty1
  @string mProperty2
}{
  mProperty1 <
}
\end{galgas4}

\begin{galgas4}
var liste1 = @maListeTriee {!3 !"a", !1 !"c"} # Valeur : (1, "c"), (3, "a")
var liste2 = @maListeTriee {!4 !"d", !2 !"b"} # Valeur : (2, "b"), (4, "d")
liste1 += liste2 # liste1 vaut (1, "c"), (2, "b"), (3, "a"), (4, "d")
\end{galgas4}



Sous la forme \ggsq*cible += !expression1 ... !expressionN*, l'instruction ajoute un élément à la fin de \ggsq+cible+. L'élément est défini par la liste des valeurs de ses champs.


On a~:

\begin{galgas4}
var liste = @maListeTriee {}
liste += !2 !"a" # Valeur : (2, "a")
liste += !1 !"b" # Valeur : (1, "b"), (2, "a")
liste += !3 !"c" # Valeur : (1, "b"), (2, "a"), (3, "c")
\end{galgas4}







\subsectionLabel{Instruction d'ajout et les tables}{instructionConcatMap}

La forme \ggsq*cible += expression* n'est pas prise en charge.

Sous la forme \ggsq*cible += !expression1 ... !expressionN*, l'instruction ajoute un élément à la table \ggsq+cible+. L'élément est défini par la clé et suivie de la liste des valeurs de ses champs.


Avec la table~:
\begin{galgas4}
map @maTable {
  @u32 mProperty1
  @string mProperty2
}
\end{galgas4}

on a~:

\begin{galgas4}
var table = @maTable {}
@lstring clef = ...
table += !clef !2 !"a"
\end{galgas4}














\sectionLabel{Affectation combinée à une opération~: \texttt{+=}, \texttt{-=}, \texttt{*=} et \texttt{/=}}{instructionAffectationCombineeOperation}

La \ggsq+cible+ est une variable ou un champ de structure.

Les instructions \ggsq!+=!, \ggsq!-=!, \ggsq!*=!, \ggsq!/=! s'appliquent~:
\begin{itemize}
 \item aux types entiers \ggsq!@s32! (\refSubsectionPage{instructionsSINT}, \ggsq!@s64! (\refSubsectionPage{instructionsSINT64}, \ggsq!@u32! (\refSubsectionPage{instructionsUINT} et \ggsq!@u64! (\refSubsectionPage{instructionsUINT64}~;
 \item au type flottant \ggsq!@double! (\refSubsectionPage{affectationsCombineesDouble}).
\end{itemize}

L'instruction \ggsq!+=! s'applique aussi au type \ggsq+@string+ (\refSubsectionPage{instructionConcatString}).

D'une manière générale, \texttt{x $op$= y} est équivalent à {x = x $op$ y}.


\subsectionLabel{Instruction \texttt{+=} et le type \texttt{@string}}{instructionConcatString}

Sous la forme \ggsq*cible += expression*, l'instruction permet de concaténer des chaînes de caractères~:
\begin{galgas4}
var s = "abc"
s += "def" # s vaut "abcdef"
\end{galgas4}

\section{L'instruction \texttt{drop}}

La syntaxe de l'instruction \ggsq+drop+ est la suivante~:

\begin{galgas4box}
drop variable, ...
\end{galgas4box}

Chaque variable nommée est placée dans l'état \emph{non construit}.

\section{L'instruction \texttt{error}}

L'instruction \ggsq+error+ permet de signaler une erreur à l'utilisateur. Elle est constituée de trois champs séparés par un double-point (\ggsq+:+)~:

\begin{galgas4box}
error localisation : message_erreur : variable1, ..., variableN
\end{galgas4box}



Le champ \ggsq+localisation+ signale à l'utilisateur la position de l'erreur dans le texte source. C'est donc une expression de type \ggsq+@location+, ou d'un type possédant un \emph{getter} sans argument nommé \ggsq+location+ et renvoyant un objet de type \ggsq+@location+~: c'est le cas des types prédéfinis \ggsq+@lu32+, \ggsq+@lu3264+, \ggsq+@ls32+, \ggsq+@ls3264+, \ggsq+@lbigint+, \ggsq+@lbool+, \ggsq+@lchar+ et \ggsq+@lstring+.

Le \ggsq+message_erreur+ est le message affiché à l'utilisateur~: c'est donc une expression de type \ggsq+@string+.

Le troisième champ liste les variables \ggsq+variable1+, ..., \ggsq+variableN+ qui sont détruites du fait de l'erreur (\refSubsectionPage{listVarDetruitesInstructionError}).

Il y a un quatrième champ, optionnel, qui permet de transmettre à l'utilisateur des suggestions de corrections~: il commence par le mot réservé \ggsq=fixit= et est décrit à la \refSubsectionPage{clauseFixItInstructionErreur}.

Si il n'y a pas de variable à citer, l'instruction s'écrit~:
\begin{galgas4}
error localisation : message_erreur
\end{galgas4}

Par exemple~:

\begin{galgas4}
$identifier$ ?@lstring nom
...
error nom.location : message_erreur
\end{galgas4}

Comme \ggsq+nom+ est de type \ggsq+lstring+ (voir ci-dessus), on peut simplement écrire~:
\begin{galgas4}
$identifier$ ?@lstring nom
...
error nom : message_erreur
\end{galgas4}


\subsectionLabel{Liste de variables détruites}{listVarDetruitesInstructionError}

Lister des variables qui ne peuvent pas être construites est indispensable dans certains cas. Examinons le code suivant (\underline{qui ne compile pas})~:
\begin{galgas4}
$identifier$ ?@lstring nom
@unType résultat
if ok then
  résultat = ...
else
  error nom : message_erreur
end # Erreur : 'résultat' est valué par une branche
\end{galgas4}

En effet, une des branches du \ggsq+if+ donne une valeur à \ggsq+résultat+, et l'autre pas. Or, en cas d'erreur, on veut que \ggsq+résultat+ ne soit pas valué à l'exécution. On écrit alors le texte suivant (qui compile)~:
\begin{galgas4}
$identifier$ ?@lstring nom
@unType résultat
if ok then
  résultat = ...
else
  error nom : message_erreur : résultat
end
\end{galgas4}

Mentionner \ggsq+résultat+ à la fin de l'instruction \ggsq+error+ permet de faire croire au compilateur que \ggsq+résultat+ est valué.


\subsectionLabel{Clause \texttt{fixit}}{clauseFixItInstructionErreur}

La clause \ggsq=fixit= est optionnelle et permet de transmettre à l'utilisateur des suggestions de corrections~: il peut apparaître à la fin d'une instruction \ggsq=error= et d'une instruction \ggsq=warning= (\refSectionPage{instructionWarning}).

Si vous utilisez l'application Cocoa engendrée par GALGAS, la liste des suggestions apparaît au début du menu contextuel \texttt{cmd-clic}~: il suffit donc d'effectuer un \texttt{cmd-clic} sur un token souligné par un trait rouge (qui signale une erreur) ou orange (une alerte) pour voir apparaître la liste des suggestions. Les suggestions concernent le token désigné par l'expression \ggsq=localisation= de l'erreur ou de l'alerte.

Sa syntaxe est la suivante~:

\begin{galgas4}
fixit {
  remove
  replace expression
  after expression
  before expression
}
\end{galgas4}

La clause \ggsq=fixit= contient une séquence de suggestions~; il existe quatre types de suggestions~:
\begin{itemize}
\item \ggsq=remove=, qui suggère d'éliminer le token désigné~;
\item \ggsq=replace=, qui suggère de remplacer le token désigné par l'\ggsq=expression= indiquée~;
\item \ggsq=after=, qui suggère d'insérer l'\ggsq=expression= indiquée après le token désigné~;
\item \ggsq=before=, qui suggère d'insérer l'\ggsq=expression= indiquée avant le token désigné.
\end{itemize}

Quatre types sont acceptés pour l'\ggsq=expression=~:
\begin{itemize}
  \item \ggsq=@string=, l'expression représente une suggestion unique~;
  \item \ggsq=@stringlist=, l'expression représente une liste de suggestions, qui seront présentées à l'utilisateur dans l'ordre de la liste~;
  \item \ggsq=@lstringlist=, l'expression représente une liste de suggestions, qui seront présentées à l'utilisateur dans l'ordre de la liste (les information de localisation sont ignorées)~;
  \item \ggsq=@stringset=, l'expression représente une liste de suggestions, qui seront présentées à l'utilisateur dans l'ordre alphabétique des chaînes.
\end{itemize}

Ainsi, on peut écrire (et de même avec \ggsq=after= et \ggsq=before=)~:
\begin{galgas4}
fixit { replace "toto" } # Suggère de remplacer le token par toto
fixit { replace "toto" replace "tata" } # Deux suggestions
fixit { replace @stringlist {!"toto" !"tata"} } # Identique au précédent
fixit { replace {!"toto" !"tata"} } # Le type @stringlist est inféré
\end{galgas4}


L'\ggsq=expression= n'est pas limitée aux constructions statiques, mais accepte des expressions calculées à l'exécution~: la liste des suggestions peut donc être calculée dynamiquement.

La clause \ggsq=fixit= contient une séquence de suggestions, qui peut être vide. Une séquence peut contenir plusieurs suggestions \ggsq=replace=, \ggsq=after=, \ggsq=before=~; par contre, la suggestion \ggsq=remove= ne peut apparaître qu'au plus une fois. Les suggestions sont présentées à l'utilisateur dans l'ordre où elles apparaissent dans la clause \ggsq=fixit=. Il est parfaitement légal d'écrire par exemple~:
\begin{galgas4}
fixit {
  replace "toto"
  after "tata"
  before "tutu"
  replace "titi"
  remove
}
\end{galgas4}


La suite présente plusieurs exemples~:
\begin{itemize}
  \item un premier exemple \ggsq=remove= sur un identificateur (\refSubsubsectionPage {premierExempleFixit})~;
  \item un exemple  \ggsq=remove= sur un mot réservé (\refSubsubsectionPage {deuxiemeExempleFixit})~;
  \item un exemple \ggsq=replace= (\refSubsubsectionPage {troisiemeExempleFixIt})~;
  \item un second exemple \ggsq=replace=, qui met en évidence un piège qui existe avec des chaînes de caractères (\refSubsubsectionPage {quatriemeExempleFixIt}).
\end{itemize}

L'utilisation de \ggsq=before= et de \ggsq=after= est analogue à celui de \ggsq=replace=~: on se reportera aux exemples \ggsq=replace= pour ceux-ci.


\subsubsectionLabel{Premier exemple \texttt{fixit remove}}{premierExempleFixit}

Supposons que votre langage contient une règle de production où un identificateur apparaît~:

\begin{galgas4}
rule <règle> ... {
  ...
  $identifier$ ?let idf
  ...
}
\end{galgas4}

Le langage change, l'identificateur n'est plus utile~; sans utiliser la clause \ggsq=fixit=, on écrit alors~:

\begin{galgas4}
rule <règle> ... {
  ...
  select
    $identifier$ ?let idf
    warning idf : "the identifier is no longer needed: remove it"
  or
  end
  ...

}
\end{galgas4}


Et en utilisant la clause \ggsq=fixit=~:

\begin{galgas4}
rule <règle> ... {
  ...
  select
    $identifier$ ?let idf
    warning idf : "the identifier is no longer needed" fixit { remove }
  or
  end
  ...

}
\end{galgas4}

Dans l'application Cocoa, le menu contextuel activé sur l'identificateur présentera la suggestion de supprimer l'identificateur.


\subsubsectionLabel{Second exemple \texttt{fixit remove}}{deuxiemeExempleFixit}

Reprenons l'exemple précédent, mais en considérant que c'est un mot réservé qui devient inutile~; on écrit~:

\begin{galgas4}
rule <règle> ... {
  ...
  select
    $mot-réservé$
    warning .here : "this keyword is no longer needed" fixit { remove }
  or
  end
  ...

}
\end{galgas4}

La différence est que l'on ne dispose pas d'une localisation explicite de l'alerte~: on est obligé d'utiliser le \refConstructorPage{location}{here} ou le \refConstructorPage{location}{next}. Utiliser à bon escient ces constructeurs est indispensable pour bien localiser le signalement.

Dans l'exemple ci-dessus, on utilise \ggsq=here=, qui désigne le token qui précède, c'est-à-dire \ggsq=$mot-réservé$=. On peut utiliser \ggsq=next=, qui désigne le token suivant, en écrivant~:

\begin{galgas4}
rule <règle> ... {
  ...
  select
    let loc = @location.next
    $mot-réservé$
    warning loc : "this keyword is no longer needed" fixit { remove }
  or
  end
  ...

}
\end{galgas4}


\subsubsectionLabel{Exemple \texttt{fixit replace}}{troisiemeExempleFixIt}

Supposons qu'un identificateur ne puisse prendre qu'un ensemble de valeurs possibles. C'est le rôle des écritures sémantiques de vérifier que la valeur est l'une de celles autorisées.

Ainsi, la règle syntaxique peut être~:
\begin{galgas4}
rule <règle> ... {
  ...
  $identifier$ ?let valeurÀVérifier
  ...
}
\end{galgas4}

Maintenant, la sémantique. Sans clause \ggsq=fixit=, elle a l'allure suivante~:
\begin{galgas4}
  let @stringset valeursPossibles = ...
  if [valeursPossibles hasKey !valeurÀVérifier] then
    ...
  else
    error valeurÀVérifier : "valeur invalide"
  end
}
\end{galgas4}

On pourrait améliorer le message d'erreur ci-dessus en ajoutant la liste des valeurs possibles. Ajouter une clause \ggsq=fixit replace= permet de le faire très simplement. Après le mot réservé \ggsq=replace= est attendue une expression de type \ggsq=@string= ou \ggsq=@stringlist=, or la variable \ggsq=valeursPossibles= est du type \ggsq=@stringset=~: on utilise donc le getter \refGetterPage{stringset}{stringList}. D'où~:

\begin{galgas4}
  let @stringset valeursPossibles = ...
  if [valeursPossibles hasKey !valeurÀVérifier] then
    ...
  else
    error valeurÀVérifier : "valeur invalide" fixit {
      replace [valeursPossibles stringList]
    }
  end
}
\end{galgas4}

\subsubsectionLabel{Exemple \texttt{fixit replace}, chaîne de caractères}{quatriemeExempleFixIt}

Reprenons l'exemple précédent, mais en supposant \ggsq=valeurÀVérifier= est obtenue à partir d'une chaîne de caractères.

\begin{galgas4}
rule <règle> ... {
  ...
  $literal_string$ ?let valeurÀVérifier
  ...
}
\end{galgas4}
%\textquotedbl

On pourrait que le fait que le terminal soit une chaîne plutôt qu'un identificateur ne change rien. Mais lorsque le terminal est une chaîne,  la valeur \ggsq=valeurÀVérifier= ne contient pas les «~"~» qui délimitent la constante chaîne de caractères. Si l'on fait le remplacement tel quel, les valeurs suggérées n'ont pas ces délimiteurs~: lors du remplacement, ils sont perdus. Aussi, il faut explicitement les rajouter avant de soumettre les suggestions~:
\begin{galgas4}
  let @stringset valeursPossibles = ...
  if [valeursPossibles hasKey !valeurÀVérifier] then
    ...
  else
    @stringlist suggestions = {}
    for (s) in valeursPossibles do
      suggestions += !"\"" + s + "\""
    end
    error valeurÀVérifier : "valeur invalide" fixit {
      replace suggestions
    }
  end
}
\end{galgas4}

\sectionLabel{L'appel de procédure}{appelRoutine}

Cette instruction permet d'exécuter une procédure. Si par exemple celle-ci est définie par~:
\begin{galgas4}
proc maRoutine !@u32 a ?!@string b {
  ...
}
\end{galgas4}

L'instruction d'appel de cette routine est (il y a plusieurs variantes possibles pour le premier paramètre qui est en entrée)~:
\begin{galgas4}
@string x = ...
maRoutine (?@u32 y !?x)
\end{galgas4}

Note~: les parenthèses sont obligatoires, même si il n'y a aucun argment.

La correspondance entre arguments formels et paramètres effectifs est décrite à la \refSectionPage{correspondanceArgFormelsParametresEffectifs}.

\sectionLabel{L'instruction \texttt{for}}{instructionFor}

L'instruction \ggsq+for+ permet d'énumérer~:
\begin{itemize}
  \item une collection~;
  \item plusieurs collections de manière synchrone.
\end{itemize}

Pour énumérer une collection, la syntaxe est la suivante~:

\begin{galgas4box}
for enumeration_collection
while condition # Optionnel
before instructions_before  # Optionnel
do
  (nom_index) # Optionnel
  instructions_do
between instructions_between  # Optionnel
after instructions_after  # Optionnel
end
\end{galgas4box}


Énumérer plusieurs collections s'exprime en séparant les différentes énumérations par une virgule~:
\begin{galgas4box}
for enumeration_collection1, enumeration_collection2, ...
while condition # Optionnel
before instructions_before  # Optionnel
do
  (nom_index) # Optionnel
  instructions_do
between instructions_between  # Optionnel
after instructions_after  # Optionnel
end
\end{galgas4box}

\subsectionLabel{Énumération « \texttt{() in expression} »}{enumerationImplicite}

Des constantes correspondants à chaque champ de l'élément courant sont implicitement déclarées (\refTableau{constantesImplicitementDeclarees}).

\begin{table}[t]
  \centering
  \begin{tabular}{lp{12cm}}
  \textbf{Type} & \textbf{Constantes implicitement déclarées}\\
  \ggsq+@data+ & \ggsq+data+, de type \ggsq+@u32+\\
  \ggsq+dict @T+ & \ggsq+key+ représente la clé, et à chaque champ de la table, correspond une constante de même nom.\\
  \ggsq+list @T+ & À chaque champ de la liste, correspond une constante de même nom.\\
  \ggsq+map @T+ & \ggsq+lkey+, de type \ggsq+@lstring+, qui représente la clé, et à chaque champ de la table, correspond une constante de même nom.\\

  \ggsq+sortedlist @T+ & À chaque champ de la liste, correspond une constante de même nom.\\
  \ggsq+@stringset+ & \ggsq+key+, de type \ggsq+@string+ \\
  \end{tabular}
  \caption{Constantes implicitement déclarées par «\texttt{() in expression}»}
  \labelTableau{constantesImplicitementDeclarees}
\end{table}

Voici quelques exemples~:
\begin{galgas4}
@data d = ...
for () in d do
  log data
end
\end{galgas4}



\begin{galgas4}
@stringset v = ...
for () in v do
  log key # Affichage des clés dans l'ordre alphabétique
end
\end{galgas4}

Avec la liste~:
\begin{galgas4}
list @maListe {
  @u32 mProperty1
  @string mProperty2
}
\end{galgas4}

On peut écrire~:

\begin{galgas4}
@maListe lst = ...
for () in lst do
  log mProperty1, mProperty2
end
\end{galgas4}


Avec la table~:
\begin{galgas4}
map @maTable {
  @u32 mProperty1
  @string mProperty2
}
\end{galgas4}

On peut écrire~:

\begin{galgas4}
@maTable tab = ...
for () in tab do
  log lkey, mProperty1, mProperty2
end
\end{galgas4}


\subsectionLabel{Énumération « \texttt{() pref{}ix in expression} »}{enumerationImplicitePrefixee}

Cette écriture est une extension de celle de la section précédente~: \ggsq+prefix+ est utilisé pour préfixer le nom des constantes implicitement déclarées. En reprenant les exemples de la section précédente~:

\begin{galgas4}
@data d = ...
for () xyz_ in d do
  log xyz_data
end
\end{galgas4}



\begin{galgas4}
@stringset v = ...
for () pre in v do
  log prekey # Affichage des clés dans l'ordre alphabétique
end
\end{galgas4}


\begin{galgas4}
@maListe lst = ...
for () lst in lst do
  log lstmProperty1, lstmProperty2
end
\end{galgas4}


\begin{galgas4}
@maTable tab = ...
for () tb_ in tab do
  log tb_lkey, tb_mProperty1, tb_mProperty2
end
\end{galgas4}

Utiliser un préfixe permet de lever les collisions des noms des constantes implicites quand on énumère des collections ayant des champs de même nom~:

\begin{galgas4}
@maListe v1 = ...
@maListe v2 = ...
for () in v1, () in v2 do # Erreur !
 ...
end
\end{galgas4}

Le compilateur GALGAS déclenche une erreur, car il y a ambiguïté sur la signification de \ggsq+mProperty1+ et de \ggsq+mProperty2+ à l'intérieur de la boucle~: désigne-t'elle l'élément courant de \ggsq+v1+ ou l'élément courant de \ggsq+v2+ ?

Pour lever l'ambiguïté, on complète l'instruction en précisant un préfixe pour l'une des deux listes (par exemple la seconde)~:
\begin{galgas4}
@maListe v1 = ...
@maListe v2 = ...
for () in v1, () l2_ in v2 do
  log mProperty1 # Désigne sans ambiguïté le champ de la première liste
  log l2_mProperty1 # Désigne sans ambiguïté le champ de la seconde liste
end
\end{galgas4}

\subsubsection{Type explicite}

On peut annoter le nom de la constante en la faisant précéder par un nom de type. Le compilateur GALGAS vérifie alors l'identité entre le type explicitement déclaré, et le type implicitement déduit du type de l'expression enumérée. Il est possible de déclarer explicitement le type de la constante en écrivant l'énumération sous la forme~:

\begin{galgas4}
@unType cst in expression
\end{galgas4}

Les exemples précédents deviennent alors~:

\begin{galgas4}
@data d = ...
for @u32 v in d do

Le \refTableau{enumerationParListeConstantes} liste pour chaque type le nombre et la signification des constantes qui doivent être déclarées.

\begin{table}[t]
  \centering
  \begin{tabular}{lp{12cm}}
  \textbf{Type} & \textbf{Constantes à déclarer}\\
  \ggsq+@data+ & \emph{Ce type n'est pas pris en charge par cette forme.}\\
  \ggsq+dict @T+ & Une constante de type de la clé, suivi d'une constante pour chaque champ de la table, dans l'ordre de déclaration.\\
  \ggsq+list @T+ & Une constante pour chaque champ, dans l'ordre de déclaration.\\
  \ggsq+map @T+ & Une constante de type \ggsq+@lstring+, qui représente la clé, suivi d'une constante pour chaque champ de la table, dans l'ordre de déclaration.\\
  \ggsq+listmap @T+ & Une constante de type \ggsq+@string+, qui représente la clé, et une constante qui représente la liste associée.\\
  \ggsq+sortedlist @T+ & Une constante pour chaque champ, dans l'ordre de déclaration.\\

  \end{tabular}

  \labelTableau{enumerationParListeConstantes}

Prenons comme exemple le type liste suivant~:
\begin{galgas4}
list @maListe {
  @u32 mProperty1
  @string mProperty2
  @char mProperty3
  @bool mProperty4
}
\end{galgas4}

L'énumération s'écrit~:
\begin{galgas4}
@maListe uneListe = {!1 !"a" !'b' !false}
for (p1 p2 p3 p4) in uneListe do
  log p1, p2, p3, p4
end
\end{galgas4}

Plusieurs variantes sont possibles, et sont décrites ci-après.

\subsubsection{Type explicite}

Il est possible d'annoter chaque constante en précisant son type.

\begin{galgas4}
@maListe uneListe = {!1 !"a" !'b' !false}
for (@u32 p1 @string p2 @char p3 @bool p4) in uneListe do
  log p1, p2, p3, p4
end
\end{galgas4}

Le compilateur vérifie alors que le type cité est égal au type déduit du type de l'expression énumérée.
\begin{galgas4}
@maListe uneListe = {!1 !"a" !'b' !false}
for (@u32 p1 @string p2 @char p3 @bool p4) in uneListe do
  log p1, p2, p3, p4
end
\end{galgas4}


\subsubsection{Joker}

Si certaines constantes ne sont pas utiles, on peut les remplacer par un joker (\ggsq+*+). Le nom du type ne doit alors pas figurer.
\begin{galgas4}
@maListe uneListe = {!1 !"a" !'b' !false}
for (@u32 p1 * * @bool p4) in uneListe do
  log p1, p4
end
\end{galgas4}

Plusieurs jokers peuvent être rassemblés en mentionnant leur nombre d'occurrences.
\begin{galgas4}
@maListe uneListe = {!1 !"a" !'b' !false}
for (@u32 p1 2* @bool p4) in uneListe do
  log p1, p4
end
\end{galgas4}



\subsubsection{Points de suspension}

Trois points consécutifs (\ggsq+...+) peuvent être utilisés pour signifier que les dernières constantes ne sont pas utiles.

\begin{galgas4}
@maListe uneListe = {!1 !"a" !'b' !false}
for (@u32 p1 ...) in uneListe do
  log p1
end
\end{galgas4}

Et si aucune constante n'est utile, on écrit~:
\begin{galgas4}
@maListe uneListe = {!1 !"a" !'b' !false}
for (...) in uneListe do

end
\end{galgas4}

\subsection{Champs optionnels}

Plusieurs champs de l'instruction \ggsq+for+ sont optionnels.


\ggsq+sens+. Ce champ peut prendre trois valeurs, et fixe l'ordre dans lequel les éléments sont énumérés~:
\begin{itemize}
  \item si le champ est vide, dans l'ordre indiqué par le \refTableau{typesEnumerablesFor}~;
  \item \ggsq+>+, dans l'ordre inverse à celui indiqué par le \refTableau{typesEnumerablesFor}.
\end{itemize}


\ggsq+(nom_index)+. Vous pouvez mentionner un identificateur entre parenthèses après le mot réservé \ggsq+do+. Cet identificateur est le nom d'une constante qui a implicitement le type \ggsq+@u32+ et qui est initialisée à 0 avant toute exécution de la boucle, et incrémentée après chaque exécution des \ggsq+instructions_do+, et avant l'exécution des \ggsq+instructions_between+. Sa visibilité est la branche \ggsq+do+.

\ggsq+while expression+. L'énumération est exécutée tant que l'\ggsq+expression+ est vraie. L'absence de cette construction est équivalent à \ggsq+while true+ et permet d'énumérer toutes les valeurs.


\ggsq+before instructions_before+. Ces instructions sont exécutées une seule fois, au début de l'exécution de l'instruction. Aucun accès aux objets énumérés n'est possible. Si l'énumération est vide, ces instructions ne sont pas exécutées.

\ggsq+between instructions_between+. Ces instructions sont exécutées entre deux exécutions consécutives des \ggsq+instructions_do+. Aucun accès aux objets énumérés n'est possible.

\ggsq+after instructions_after+. Ces instructions sont exécutées une seule fois, à la fin de l'exécution de l'instruction. Aucun accès aux objets énumérés n'est possible. Si l'énumération est vide, ces instructions ne sont pas exécutées.


\subsection{Modification de la collection}

Au début de l'exécution de l'instruction \ggsq+for+, les valeurs des collections enumérées sont capturées et mémorisées. L'énumération s'effectue sur ces valeurs mémorisées. Aussi, il est possible de modifier la collection en cours d'énumération sans que cela affecte l'exécution~:
\begin{galgas4}
@stringlist v = {!"A", !"B", !"C"}
log v # "A", "B", "C"
for s in v do
  v += !s
end for
log v # "A", "B", "C", "A", "B", "C"
\end{galgas4}












\section{L'instruction \texttt{if}}


Dans sa forme la plus générale, l'instruction \ggsq+if+ a la syntaxe suivante:

\begin{galgas4box}
if condition then
  instructions
elsif condition2 then
  instructions2
...
else
  instructions_else
end
\end{galgas4box}


Plus précisement, elle contient~:
\begin{itemize}
\item zéro, une ou plusieurs branches \ggsq+elsif+~;
\item zéro ou une branche \ggsq+else+.
\end{itemize}


Aucune branche \ggsq+else+ est équivalent à une branche \ggsq+else+ sans aucune instruction.


Les branches \ggsq+elsif+ sont simplement du sucre syntaxique~: il est sémantiquement équivalent d'utiliser des instructions \ggsq+if+ imbriquées. Par exemple~:
\begin{galgas4}
if condition then
  instructions
elsif condition2 then
  instructions2
else
  instructions_else
end
\end{galgas4}

est équivalent à~:
\begin{galgas4}
if condition then
  instructions
else
  if condition2 then
    instructions2
  else
    instructions_else
  end
end
\end{galgas4}

Le langage permet plusieurs aux conditions notées \ggsq+condition+ et \ggsq+condition2+ dans les exemples ci-dessus :
\begin{itemize}
  \item soit une simple expression ;
  \item soit une affectation conditionnelle ;
  \item soit une liste de simples expressions et d'affectations conditionnelles.
\end{itemize}


\subsection{Simple expression}
Le langage permet que le type des \ggsq+condition+ et \ggsq+condition2+ soit différent du type \refTypePredefini{bool}, sous certaines conditions. La règle complète est que le type des \ggsq+condition+ et \ggsq+condition2+ est~:
\begin{itemize}
\item soit le type \ggsq+@bool+~;
\item soit un type \emph{structure}, possèdant une propriété nommée \ggsq+bool+, dont le type est \ggsq+@bool+;
\item soit un type possédant un \emph{getter} sans argument nommé \ggsq+bool+ et renvoyant une valeur de type \ggsq+@bool+.
\end{itemize}

Voici un exemple illustrant le deuxième cas~; le type \refTypePredefini{bool} est une structure possèdant une propriété nommée \ggsq+bool+, dont le type est \ggsq+@bool+. Aussi, écrire~:

\begin{galgas4}
@lbool variable = ...
if variable then
  instructions
else
  else_instructions
end
\end{galgas4}


est équivalent à~:
\begin{galgas4}
@lbool variable = ...
if variable.bool then
  instructions
else
  else_instructions
end
\end{galgas4}


Pour illustrer le troisième cas, on prend l'exemple de la classe suivante~:
\begin{galgas4}
class @myClass { ... }

getter @myClass bool -> @bool outResult { ... }
\end{galgas4}

Ainsi, on peut écrire~:
\begin{galgas4}
@myClass myObject = ...
if myObject then
  instructions
else
  else_instructions
end
\end{galgas4}


Il est équivalent d'écrire~:
\begin{galgas4}
@myClass myObject = ...
if [myObject bool] then
  instructions
else
  else_instructions
end
\end{galgas4}


\subsectionLabel{L'affectation conditionnelle}{affectationConditionnelle}

L'affectation conditionnelle a la syntaxe suivante~:
\begin{galgas4}
if let cible = expression as @T then
  then_instructions # cible est défini, du type @T
else
  else_instructions # cible n'est pas défini
end
\end{galgas4}

Si l'\ggsq=expression= est de type \ggsq=@T=, alors la condition est vraie et les \ggsq=then_instructions= sont exécutées. La constante\ggsq=cible= est définie dans ces instructions, elle a pour type \ggsq=@tT= et pour valeur celle de l'\ggsq=expression=.

Si l'\ggsq=expression= n'est pas de type \ggsq=@T=, alors la condition est fausse et les \ggsq=else_instructions= sont exécutées. La constante\ggsq=cible= n'est pas définie dans ces instructions.

L'affectation conditionnelle permet de faire une affectation polymorphique inverse de manière propre, sans utiliser l'\emph{expression de conversion polymorphique inverse} (\ggsq=expression as @T=, \refSubsectionPage{expConversionPolymorphiqueInverse}).


\subsection{Liste de simples expressions et d'affectations conditionnelles}

La condition d'une instruction \ggsq=if= peut être une liste simples expressions et d'affectations conditionnelles, le séparateur étant la virgule \ggsq=,=. L'évaluation s'effectue de gauche à droite, sous la forme d'un court-circuit~:
\begin{itemize}
\item dès qu'une condition ou affectation conditionnelle n'est pas vraie (c'est-à-dire fausse ou non construite), les éléments suivants ne sont pas évalués et la condition est fausse ;
\item la condition est vraie si les évaluations de gauche à droite de toutes les simples expressions et affectations conditionnelles sont vraies.
\end{itemize}

Le résultat d'une affectation conditionnelle peut être utilisé dans les éléments suivants~:
\begin{galgas4}
if let cible = exp as @T, let cible2 = [cible unGetter] as @U then
  then_instructions # cible et cible2 sont définis
else
  else_instructions # Ni cible ni cible2 ne sont définis
end
\end{galgas4}







\sectionLabel{L'instruction \texttt{grammar}}{instruction-grammar}

L'instruction \ggsq+grammar+ permet d'exécuter l'analyse d'un texte par une grammaire. Le texte peut être contenu~:
\begin{itemize}
  \item dans un fichier (\refSubsectionPage{texteSourceDansFichier})~;
  \item dans une chaîne de caractères (\refSubsectionPage{texteSourceDansChaine}).
\end{itemize}










\subsectionLabel{Texte source dans un fichier}{texteSourceDansFichier}

\begin{galgas4box}
grammar
  nom_grammaire
  label_grammaire # Optionnel
  (liste_parametres)
  in expression # Chemin du fichier source
  traduction_dirigee_par_la_syntaxe # Optionnel
\end{galgas4box}

Le mot réservé \ggsq!in! caractérise la localisation de la chaîne source dans un fichier.
\begin{itemize}
  \item \ggsq+nom_grammaire+ est un identificateur nommant la grammaire, c'est le nom d'un composant grammaire du projet~;
  \item \ggsq+label_grammaire+ est optionnel, et permet d'exécuter une variante des règles de production (voir \refSectionPage{analysePlusieursPhases})~;
  \item \ggsq+liste_parametres+ est une liste de paramètres effectifs (en entrée, sortie, ou sortie/entrée), en accord avec la liste des arguments formels de l'axiome de la grammaire~;
  \item \ggsq+expression+ est une valeur de type \ggsq+@lstring+, dont le champ \ggsq+string+ désigne un fichier source, par un chemin relatif ou absolu, et dont le champ \ggsq+location+ est la position de signalement d'erreur si le fichier source ne peut pas être lu~;
  \item \ggsq+traduction_dirigee_par_la_syntaxe+ est optionnel, et permet d'obtenir la chaîne source traduite lors d'une \emph{traduction dirigée par la syntaxe} (voir \refSectionPage{instructionGrammarEtTraductionDirigeeParLaSyntaxe}).
\end{itemize}

Prenons l'exemple d'un composant grammaire~:
\begin{galgas4}
grammar maGrammaire "SLR" {
  syntax ...
   <start_symbol> (?!@declarationAST ioDeclarations)
}
\end{galgas4}

L'instruction grammaire s'écrit alors~:
\begin{galgas4}
grammar maGrammaire (!?ioDeclarations) in fichierSource
\end{galgas4}

Cette instruction est typiquement utilisé dans une règle d'analyse de fichier source (\refChapterPage{regleAnalyseFichierSource})~:

\begin{galgas4}
case . "monExtension"
message "un fichier source"
grammar maGrammaire
?sourceFilePath: @lstring inSourceFile {
  var declaration = @declarationList {}
  grammar maGrammaire (!?ioDeclarations) in inSourceFile
  ...
}
\end{galgas4}




\subsectionLabel{Texte source dans une chaîne de caractères}{texteSourceDansChaine}
\begin{galgas4box}
grammar
  nom_grammaire
  label_grammaire # Optionnel
  (liste_parametres)
  on chaine_source : nom_associe
  traduction_dirigee_par_la_syntaxe # Optionnel
\end{galgas4box}

Le mot réservé \ggsq!on! caractérise la localisation de la chaîne source dans une chaîne de caractères.
\begin{itemize}
  \item \ggsq+nom_grammaire+ est un identificateur nommant la grammaire, c'est le nom d'un composant grammaire du projet~;
  \item \ggsq+label_grammaire+ est optionnel, et permet d'exécuter une variante des règles de production (voir \refSectionPage{analysePlusieursPhases})~;
  \item \ggsq+liste_parametres+ est une liste de paramètres effectifs (en entrée, sortie, ou sortie/entrée), en accord avec la liste des arguments formels de l'axiome de la grammaire~;
  \item \ggsq+chaine_source+ est une expression de type \ggsq!@string!, qui contient directement la chaîne source à analyser~;
  \item \ggsq+nom_associe+ est une expression de type \ggsq!@string!, qui est utilisé lorsque \ggsq!@location.here! est appelé~: \ggsq![@location.here file]! renvoie la valeur transmise dans \ggsq+nom_associe+~;
  \item \ggsq+traduction_dirigee_par_la_syntaxe+ est optionnel, et permet d'obtenir la chaîne source traduite lors d'une \emph{traduction dirigée par la syntaxe} (voir \refSectionPage{instructionGrammarEtTraductionDirigeeParLaSyntaxe}).
\end{itemize}



La chaîne \ggsq+nom_associe+ sert lorsque qu'une erreur est détectée lors de l'analyse de \ggsq+chaine_source+. On a alors un message d'erreur dont la première ligne est~:

\texttt{nom\_associe:ligne:colonne:}

Ce message est alors similaire au message que l'on obtient lors que l'on analyse un fichier, où le message dont la première ligne est~:

\texttt{nom\_fichier\_source:ligne:colonne:}














\sectionLabel{L'instruction \texttt{guard}}{instruction-guard}

L'instruction \ggsq+guard+ est une variante syntaxique de l'instruction \ggsq+if+. Voici un exemple d'instruction \ggsq+if+, comment elle peut être re-écrite en instruction \ggsq+guard+ et l'avantage qui en résulte.

\begin{galgas4box}
if condition1 then
  instructions1
  if condition2 then
    instructions2
  else
    erreur2
  end
else
  erreur1
end
\end{galgas4box}

On peut considérer que cette écriture présente plusieurs inconvénients~:
\begin{itemize}
  \item si \ggsq+instructions1+ et \ggsq+instructions2+ comportent de nombreuses lignes, les instructions des branches \ggsq+else+ sont loin du début de l'instruction \ggsq+if+ correspondante~;
  \item à chaque instruction \ggsq+if+, l'indentation des instructions incluses augmente.
\end{itemize}

L'instruction \ggsq+guard+ permet d'exprimer la même sémantique sous une forme syntaxique différente~:

\begin{galgas4box}
guard condition1 else
  erreur1
end
instructions1
guard condition2 else
  erreur2
end
instructions2
\end{galgas4box}

L'avantage que l'on peut y voir est :
\begin{itemize}
  \item la branche \ggsq+else+ est écrite en premier, ce qui permet d'évacuer rapidement les cas d'erreur~;
  \item les \ggsq+instructions1+ et \ggsq+instructions2+ ne subissent plus d'indentation suppémentaire.
\end{itemize}

D'un point de vue sémantique, les instructions \ggsq+guard+ et \ggsq+if+ sont équivalentes, seules leurs syntaxes diffèrent (\refFigure{}{instructionsIFetGUARD}). La branche \ggsq+else+ d'une instruction \ggsq+guard+ est obligatoire (même si elle est vide), contrairement à celle d'une instruction \ggsq+if+ où elle peut être omise.

    ~~\emph{instructions\_then}\\
    \textbf{else}\\
    ~~\emph{instructions\_else}\\
    \textbf{end}\\
    \end{tabular}
  }
  \hspace{1cm}
  \subfloat[Instruction \texttt{guard}] {
    \tt
    \begin{tabular}{l}
    \textbf{guard} \emph{condition} \textbf{else}\\
    ~~\emph{instructions\_else}\\
    \textbf{end}\\
    \emph{instructions\_then}\\
    \end{tabular}
  }

\section{L'instruction \texttt{loop}}


L'instruction \ggsq+loop+ a la syntaxe suivante~:
\begin{galgas4box}
loop (variant_expression)
  instructions_1
while expression do
  instructions_2
end
\end{galgas4box}


Les \ggsq+instructions_1+ et \ggsq+instructions_2+ sont des listes d'instructions qui peuvent être vides.


Le \ggsq+variant_expression+ est une expression de type \ggsq+@u32+ qui assure que la boucle n'est pas sans fin~: elle est calculée au début de l'exécution de l'instruction, et décrémentée après chaque itération. Si sa valeur atteint zéro, une erreur d'exécution est déclenchée.

L'\ggsq+expression+ est une expression de type \ggsq+@bool+ qui exprime la continuation de l'exécution de la boucle.

\sectionLabel{L'instruction d'appel de procédure}{instructionAppelProcedure}

La syntaxe de l'appel d'une procédure est~:
\begin{galgas4box}
nom_procedure (liste_parametres_effectifs)
\end{galgas4box}

Les parenthèses sont obligatoires. La déclaration d'un procédure est présentée à la \refSectionPage{declarationProcedure}.

\ggsq+nom_procedure+ est le nom de la procédure, et \ggsq+liste_parametres_effectifs+ est la liste des paramètres effectifs de l'appel, en accord avec l'en-tête de la procédure.

Par exemple, la procedure suivante~:
\begin{galgas4}
proc produit ?@u32 a ?@u32 b !@u32 résultat {
  résultat = a * b
}
\end{galgas4}

Peut être appelée par~:
\begin{galgas4}
produit (!2 !3 ?@u32 résultat)
\end{galgas4}















\sectionLabel{L'instruction d'appel de méthode}{methodCallInstruction}

En GALGAS, une \emph{méthode} est un sous-programme qui s'applique à un objet, et qui ne modifie pas cet objet. La syntaxe de l'appel d'une méthode est~:
\begin{galgas4}
[expression nom_methode liste_parametres_effectifs]
\end{galgas4}

La valeur d'\ggsq+expression+ est l'objet sur lequel la méthode est appelée, \ggsq+nom_methode+ est le nom de la méthode, et \ggsq+liste_parametres_effectifs+ est la liste des paramètres effectifs, en accord avec l'en-tête de la méthode.

Avec l'option \texttt{-T}, un fichier HTML qui contient les caractéristiques de tous les types d'un projet est engendré dans le répertoire \texttt{build/helpers}. Ainsi, les en-têtes de toutes les méthodes sont listés. Par exemple, pour le type \ggsq+@string+, la méthode \ggsq+writeToExecutableFileWhenDifferentContents+ est présentée comme suit~:

\begin{galgas4}
method writeToExecutableFileWhenDifferentContents
  ?@string inFilePath
  !@bool outFileModified
\end{galgas4}


Aussi, cette méthode peut être appelée par~:
\begin{galgas4}
@string contents = ...
@string filePath = ...
[contents writeToExecutableFileWhenDifferentContents
  !filePath
  ?@bool fileChanged
]
\end{galgas4}















\sectionLabel{L'instruction d'appel de procédure de classe}{classProcCallInstruction}

En GALGAS, une \emph{procédure de classe} est est une procédure définie dans un type. Au contraire d'une méthode, elle ne s'applique pas à un objet. La syntaxe de l'appel d'une procédure de classe est~:
\begin{galgas4}
[@T nom_procedure liste_parametres_effectifs]
\end{galgas4}

\ggsq+nom_procedure+ est le nom de la procédure, et \ggsq+liste_parametres_effectifs+ est la liste des paramètres effectifs, en accord avec l'en-tête de la procédure.

Avec l'option \tpp{-T}, un fichier HTML qui contient les caractéristiques de tous les types d'un projet est engendré dans le répertoire \tpp{build/helpers}. Ainsi, les en-têtes de toutes les méthodes sont listés. Par exemple, pour le type \ggsq+@string+, la procédure de classe \ggsq+deleteFile+ est présentée comme suit~:

{\noindent\ttfamily
\textbf{proc} @string deleteFile ?@string inFilePath\\
}

Aussi, elle peut être appelée par~:
\begin{galgas4}
@string filePath = ...
[@string deleteFile !filePath]
\end{galgas4}









\sectionLabel{L'instruction d'appel de \emph{setter}}{setterCallInstruction}


En GALGAS, un \emph{setter} est un sous-programme qui s'applique à un objet, et qui peut modifier cet objet. L'instruction d'appel accepte deux formes différentes.

\subsection{Appel simple}

La première syntaxe de l'appel d'un  \emph{setter} est~:
\begin{galgas4}
[!?cible nom_setter liste_parametres_effectifs]
\end{galgas4}

Le délimiteur \ggsq+!?+  devant \ggsq+cible+ permet de distinguer syntaxiquement un appel de \emph{setter} d'un appel de méthode. \ggsq+cible+ désigne l'objet sur lequel le \emph{setter} est appelé, et peut être une variable, ou le champ d'une variable (\ggsq+variable.champ+), ou le champ d'un champ d'une variable (\ggsq+variable.champ.champ2+), ... \ggsq+nom_setter+ est le nom du \emph{setter}, et \ggsq+liste_parametres_effectifs+ est la liste des paramètres effectifs, en accord avec l'en-tête du \emph{setter}.

Avec l'option \texttt{-T}, un fichier HTML qui contient les caractéristiques de tous les types d'un projet est engendré dans le répertoire \texttt{build/helpers}. Ainsi, les en-têtes de toutes les \emph{setters} sont listées. Par exemple, pour le type \ggsq+@string+, le \emph{setter} \ggsq+setCharacterAtIndex+ est présenté comme suit~:

\begin{galgas4}
setter setCharacterAtIndex
  ?@char inChar
  ?@u32 inIndex
\end{galgas4}

Aussi, ce \emph{setter} peut être appelé par~:
\begin{galgas4}
@string s = ...
[!?s setCharacterAtIndex !'a' !4]
\end{galgas4}


\subsection{Appel avec conversion de type}

La seconde syntaxe de l'appel d'un  \emph{setter} est~:

\begin{galgas4}
[!?cible as @T nom_setter liste_parametres_effectifs]
\end{galgas4}

Statiquement, le type \ggsq+@T+ doit être un type héritier du type statique de \ggsq+cible+.

À l'exécution, si le type dynamique est le type \ggsq+@T+ ou un de ses héritiers, l'instruction est exécutée. Sinon, une erreur d'exécution a lieu et le setter n'est pas appelé.

Par exemple, on considère les déclarations de classe et le setter suivant~:

\begin{galgas4}
class @a { }

class @b : @a { }

setter @b aSetter { }
\end{galgas4}

Si on écrit~:
\begin{galgas4}
@a unObjet = ...
[!?unObjet aSetter] # Erreur sémantique
\end{galgas4}

L'instruction \ggsq+[!?unObjet aSetter]+ donne lieu à une erreur sémantique, puisque la classe \ggsq+@a+ ne définit pas le setter \ggsq+aSetter+.

L'écriture suivante est acceptée par le compilateur car la classe \ggsq+@b+ définit le setter \ggsq+aSetter+~:
\begin{galgas4}
@a unObjet = ...
[!?unObjet as @b aSetter] # Compilation ok
\end{galgas4}

À l'exécution, le comportement dépend du type dynamique de \ggsq+unObjet+. Si celui-ci est une instance de \ggsq+@a+, une erreur d'exécution est déclenchée~:
\begin{galgas4}
@a unObjet = @a.new
[!?unObjet as @b aSetter] # Compilation ok, erreur d'exécution
\end{galgas4}


Par contre, si \ggsq+unObject+ est une instance de \ggsq+@b+, l'appel du setter d'effectue~:
\begin{galgas4}
@a unObjet = @b.new
[!?unObjet as @b aSetter] # Compilation ok, appel du setter
\end{galgas4}










\sectionLabel{L'instruction \texttt{switch}}{instructionSwitch}

L'instruction \ggsq+switch+ est dédiée aux types énumérés. Elle présente la syntaxe suivante~:

\begin{galgas4}
switch expression
case constante, constante, ... :
  liste_instructions
case constante, constante, ... :
  liste_instructions
...
end
\end{galgas4}


Où \ggsq+expression+ est une expression d'un type énuméré. Toutes les constantes de ce type doivent être nommées dans les branches \ggsq+case+, une et une seule fois.

Par exemple, avec la déclaration~:

\begin{galgas4}
enum @feuTricolore {
  case vert
  case orange
  case rouge
}
\end{galgas4}

On peut écrire~:

\begin{galgas4}
@feuTricolore feu = ...

switch feu
case vert, orange:
  ...
case rouge :
  ...
end
\end{galgas4}

Si des constantes déclarées dans l'énumération ont des valeurs associées, alors les branches \ggsq+case+ nommant ces constantes doivent adopter une syntaxe particulière.

En prenant pour exemple une constante possédant deux valeurs associées, la forme la plus générale est~:

\begin{galgas4}
switch expression
case constante (@type1 nom1 @type2 nom2) :
...
end
\end{galgas4}

\ggsq+nom1+ et \ggsq+nom2+ sont des constantes qui reçoivent les valeurs associées.

Si on n'est pas intéressé par une valeur, on peut substituer \ggsq+*+ au nom~:

\begin{galgas4}
switch expression
case constante (@type1 nom1 @type2 *) :
...
end
\end{galgas4}

De même, l'annotation du type est optionnel~: les types \ggsq+@type1+, \ggsq+@type2+ peuvent être déduits de la déclaration de la valeur associée~:

\begin{galgas4}
switch expression
case constante (nom1 *) :
...
end
\end{galgas4}

Ainsi, si l'on n'est pas intéressé par les valeurs associées, on peut écrire~:
\begin{galgas4}
switch expression
case constante (* *) :
...
end
\end{galgas4}

Ou aussi~:
\begin{galgas4}
switch expression
case constante (2*) :
...
end
\end{galgas4}


Ou utiliser le mot clé \ggsq+unused+ (avec ou sans annotation de type)~:
\begin{galgas4}
switch expression
case constante (@type1 unused nom1 unused nom2) :
...
end
\end{galgas4}


Enfin, on peut mentionner dans la même branche \ggsq+case+ plusieurs constantes déclarant des valeurs associées, à la condition que ces valeurs associées soient de même nombre et de même type. Par exemple~:

\begin{galgas4}
enum @erreur {
  case ok
  case erreur1 (@string unMessage)
  case erreur2 (@string autreMessage)
}
\end{galgas4}

On peut écrire l'instruction \ggsq+switch+ correspondante~:
\begin{galgas4}
@erreur erreur = ...

switch erreur
case ok:
  ...
case erreur1, erreur2 (@string m) :
  ...
end
\end{galgas4}




\sectionLabel{L'instruction \texttt{warning}}{instructionWarning}

L'instruction \ggsq+warning+ permet de signaler une alerte à l'utilisateur. Elle est constituée de deux champs séparés par un double-point (\ggsq+:+)~:

\begin{galgas4}
warning localisation : message_alerte
\end{galgas4}



Le champ \ggsq+localisation+ signale à l'utilisateur la position de l'erreur dans le texte source. C'est donc une expression de type \ggsq+@location+, ou d'un type possédant un \emph{getter} sans argument nommé \ggsq+location+ et renvoyant un objet de type \ggsq+@location+~: c'est le cas dses types prédéfinis \ggsq+@lu32+, \ggsq+@lu3264+, \ggsq+@ls32+, \ggsq+@ls3264+, \ggsq+@lbigint+, \ggsq+@lbool+, \ggsq+@lchar+ et \ggsq+@lstring+.


Le \ggsq+message_alerte+ est le message affiché à l'utilisateur~: c'est donc une expression de type \ggsq+@string+.

Il y a un troisième champ, optionnel, qui permet de transmettre à l'utilisateur des suggestions de corrections~: il commence par le mot réservé \ggsq=fixit= et est décrit à la \refSubsectionPage{clauseFixItInstructionErreur}.

Exemple d'instruction \ggsq=warning=~:

\begin{galgas4}
$identifier$ ?@lstring nom
...
warning nom.location : message_alerte
\end{galgas4}

Comme \ggsq+nom+ est de type \ggsq+@lstring+ (voir ci-dessus), on peut simplement écrire~:
\begin{galgas4}
$identifier$ ?@lstring nom
...
warning nom : message_alerte
\end{galgas4}
